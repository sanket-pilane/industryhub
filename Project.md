# INDUSTRIHUB — Codex Build Specification

> Copy this file into the root of the implementation repository and ask Codex to execute it phase by phase. This document is both the product brief and the engineering acceptance contract.

## 1. Codex Mission

Build **INDUSTRIHUB**, a production-structured, responsive industrial B2B e-commerce and custom-manufacturing platform.

The platform must:

- Match the existing Figma prototype closely on desktop and mobile.
- Be implemented with **Next.js + TypeScript**.
- Run locally with realistic seed data before cloud resources are available.
- Use **Zoho Catalyst** for Authentication, Functions, Data Store, Stratus file storage, email, and Slate hosting.
- Support three role-aware workspaces: **Customer**, **Supplier**, and **Admin**.
- Implement real navigation, forms, search, filters, validation, data state, loading states, empty states, and error states—not static slideshow screens.
- Preserve a clean architecture so mock services can be replaced with Catalyst services without rewriting UI components.

### Source of truth

- Product name: `INDUSTRIHUB`
- Figma design: https://www.figma.com/design/Tqt0gIyXS1ceEhPZgRLh8U
- Demo logged-in customer: **Srushti Shinde**, initials `SS`
- Currency: `INR`
- Primary market assumptions: Indian industrial buyers and suppliers; support GST invoices and GSTIN fields.

Do not invent project IDs, organization IDs, ZAIDs, table IDs, payment credentials, or production URLs.

## 3. Architecture Decision

Use the following architecture for the first release:

```text
Next.js web application
  └── Zoho Catalyst Slate
        ├── Catalyst Web SDK authentication
        └── HTTPS calls with generated auth token

Catalyst Advanced I/O function: api
  ├── Authentication and role authorization
  ├── Product/catalog endpoints
  ├── Cart/order/checkout endpoints
  ├── Drawing/RFQ/quotation endpoints
  ├── Supplier endpoints
  ├── Admin endpoints
  └── Support/invoice/tracking endpoints

Catalyst services
  ├── Authentication: application users and sessions
  ├── Data Store: relational business records
  ├── Stratus: drawings, images, QC files and invoices
  ├── Email: transactional notifications
  └── Job Scheduling/Signals: later asynchronous processing
```

### Why this architecture

- Slate is the Catalyst-native home for Next.js.
- Functions are preferred over a persistent AppSail service for stateless APIs.
- Data Store fits orders, products, quotations, jobs, suppliers, invoices, and tickets.
- Stratus must be used for binary files. Do not store file bytes in Data Store.
- AppSail is not needed for the MVP. Introduce it only if a future CAD-processing worker requires a persistent process or custom container.

### Local-first adapter design

Support two application modes:

```env
NEXT_PUBLIC_DATA_MODE=mock
NEXT_PUBLIC_DATA_MODE=catalyst
```

- `mock`: local fixtures and deterministic simulated API latency/errors.
- `catalyst`: Catalyst Authentication + absolute Catalyst Function URL.
- UI components must depend on typed repositories/services, not directly on fixture files or Catalyst SDK calls.

## 10. Custom Manufacturing Workflow

Implement and validate this server-side state machine:

```text
DRAFT
  → SUBMITTED
  → UNDER_ENGINEERING_REVIEW
  → QUOTED
  → ACCEPTED
  → ADVANCE_PENDING
  → ADVANCE_PAID
  → SUPPLIER_ASSIGNMENT
  → IN_PRODUCTION
  → QC_IN_PROGRESS
  → QC_APPROVED
  → READY_TO_DISPATCH
  → DISPATCHED
  → DELIVERED
```

Supported side states:

```text
REVISION_REQUESTED
ON_HOLD
REJECTED
CANCELLED
QC_REJECTED
```

Every transition must:

- Check role and ownership.
- Validate allowed previous states.
- Append a status-history row.
- Record who changed the state and when.
- Return the updated resource.
- Trigger a notification asynchronously where applicable.

### Catalyst Data Store rules

- Table and column names are case-sensitive.
- ZCQL SELECT returns wrapped results. Always unwrap with `result.map(row => row.TableName).filter(Boolean)`.
- ZCQL returns at most 300 rows; implement pagination.
- Data Store booleans may cross the API boundary as strings. Convert with `value === 'true' || value === true`, and write consistent string values when required.
- App User write permissions are off by default. Prefer protected function endpoints and explicitly configure required table permissions.

## 14. Stratus Storage Design

Use a globally unique bucket name based on the project, for example:

```text
industrihub-<project-id-prefix>
```

Object-key conventions:

```text
product-images/{productId}/{uuid}.{ext}
drawings/{customerId}/{requestId}/{revision}/{uuid}.{ext}
qc/{supplierId}/{jobId}/{uuid}.{ext}
invoices/{customerId}/{orderId}/{invoiceNumber}.pdf
support/{ticketId}/{uuid}.{ext}
```

Drawing upload flow:

1. `POST /api/drawings/upload-intent`
2. Backend validates identity, extension, declared size, and ownership.
3. Backend creates a unique object key and short-lived Stratus PUT pre-signed URL.
4. Browser uploads directly to Stratus and reports progress.
5. `POST /api/drawings/complete`
6. Backend verifies object existence, writes `Drawings`, and creates/updates the manufacturing request.

Do not expose unrestricted bucket credentials. Download links for private files must be short-lived and ownership-checked.

## 16. Catalyst Authentication and API Security

- Use Catalyst Web SDK for browser authentication.
- `isUserAuthenticated()` returns a user object and rejects with 401 when unauthenticated; it is not a boolean-only call.
- `signOut()` requires a redirect URL and is not awaited.
- Slate and Functions are different domains.
- Use an absolute Function URL.
- Before protected API calls, obtain `catalyst.auth.generateAuthToken()` and send the raw token in the `Authorization` header.
- In the function, initialize user scope to identify the current user, then use admin scope for authorized server-side Data Store/Stratus work.
- Require authentication for every function that reads/writes customer, supplier, payment, drawing, or admin data.
- Do not trust a role, customer ID, supplier ID, price, tax, or total supplied by the browser.
- Recalculate cart and quotation totals server-side.
- Add localhost CORS only for local development. For deployed Slate, configure Authorized Domains and let the Catalyst gateway supply production CORS headers to avoid duplicates.
- Development and Production ZAIDs differ. Never hardcode ZAID into source code.
- Never assign App Administrator to ordinary users.

## 18. Search and Filtering Logic

Search must be functional, not a link to a static screen.

- Debounce catalog and quotation queries by approximately 250 ms.
- Keep filters in URL search parameters.
- Reset page to 1 when filters change.
- Show applied-filter chips with individual removal and Reset All.
- Show skeletons while loading.
- Show a useful no-results state with suggestions and Clear Filters.
- Use server-side filtering and pagination in Catalyst mode.
- Users may only search records they are authorized to view.
- Desktop and mobile must share the same filter state and API contract.

## 19. AI Feature Roadmap

Keep AI integrations behind an `AiService` interface. Do not block the core MVP on them.

### Phase A: safe, useful assistance

- Natural-language product search translated into catalog filters.
- Drawing filename/type classification and basic document metadata extraction.

- Missing-information checks for quantity, material, tolerance, finish, and delivery date.
- Supplier suggestions based on configured process/material/capability rules.
